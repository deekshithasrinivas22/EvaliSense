# EvaliSense — Data & Dataset Guide

## Data Directory Structure

```
data/
├── raw/                     # Original handwritten answer images
│   ├── .gitkeep
│   └── answer_*.png         # Generated by create_test_images.py
│
├── processed/               # Preprocessed images (output of preprocessing)
│   └── .gitkeep
│
├── samples/                 # Sample rubrics, answers, and synthetic datasets
│   ├── sample_rubric.json              # Photosynthesis (Biology, 10 marks)
│   ├── rubric_cell_biology.json        # Cell Biology (Biology, 10 marks)
│   ├── rubric_industrial_revolution.json  # Industrial Revolution (History, 15 marks)
│   ├── rubric_newtons_laws.json        # Newton's Laws (Physics, 12 marks)
│   ├── sample_answers.json             # 8 typed student answers at varying quality
│   └── synthetic_dataset.jsonl         # Generated by generate_synthetic_dataset.py
│
├── annotations/             # Expert annotations (future: examiner-verified marks)
│   └── .gitkeep
│
└── results/                 # Evaluation outputs and ground-truth records
    ├── .gitkeep
    ├── demo_results.jsonl               # Generated by run_demo.py
    └── completed_evaluations.jsonl      # Generated by examiner reviews via API
```

## Three Types of Data

### Type A — Real Data (Does Not Exist Yet)
- Real scanned handwritten exam answers
- Real expert marks from qualified examiners
- **Status**: Not available. Must be collected from actual examination settings.
- **Action needed**: Collect handwritten answer scans and have examiners grade them.

### Type B — Demonstration/Sample Data ✅
- Programmatic images from `create_test_images.py` (OpenCV rendered text, NOT real handwriting)
- Typed sample answers in `sample_answers.json` (simulating HTR output)
- Sample rubrics across 4 subjects
- **Purpose**: Pipeline testing, UI demonstration, integration testing
- **Can be used for**: Verifying the system works end-to-end
- **Cannot be used for**: Evaluating HTR accuracy or reporting real model performance

### Type C — Synthetic Data ✅
- Generated by `generate_synthetic_dataset.py`
- Random feature distributions with realistic ranges
- AI marks and expert marks with controlled noise
- **Purpose**: ML model development, training pipeline validation
- **Can be used for**: Testing model training/evaluation code works correctly
- **Cannot be used for**: Claiming real-world grading-error prediction accuracy

## How to Create Data

### Step 1: Create test images
```bash
python create_test_images.py
# Creates 6 test images in data/raw/
```

### Step 2: Generate synthetic training data
```bash
python generate_synthetic_dataset.py --count 200 --output data/samples/synthetic_dataset.jsonl
# Creates 200 synthetic ground-truth records
```

### Step 3: Run the demo pipeline
```bash
python run_demo.py --train-model
# Evaluates 8 sample answers, creates ground-truth, optionally trains model
```

### Step 4: Collect real data (future)
```
1. Scan handwritten exam answers → data/raw/
2. Start the server: uvicorn api.app:app --port 8000
3. Upload images through the UI
4. Run HTR → Evaluate → Predict Risk
5. Enter examiner marks → creates real ground-truth records
6. Records saved to data/results/completed_evaluations.jsonl
7. Re-train model with real data
```

## Dataset Formats

### Rubric (JSON)
```json
{
  "question": "...",
  "max_marks": 10,
  "reference_answer": "...",
  "criteria": [
    {
      "id": "c1",
      "description": "...",
      "marks": 2,
      "keywords": ["keyword1", "keyword2"]
    }
  ],
  "metadata": { "subject": "Biology", "is_synthetic": true }
}
```

### Ground-Truth Record (JSONL — one per line)
```json
{
  "record_id": "abc123",
  "question": "...",
  "student_answer": "...",
  "ai_mark": 7.0,
  "expert_mark": 6.0,
  "max_marks": 10.0,
  "absolute_error": 1.0,
  "is_grading_error": false,
  "features": {
    "ocr_confidence": 0.72,
    "overall_semantic_similarity": 0.65,
    "mean_criterion_similarity": 0.58,
    "evaluation_confidence": 0.61,
    "...": "..."
  },
  "metadata": { "source": "examiner_review", "is_synthetic": false }
}
```

### Feature Schema (16 features)
| # | Feature | Range | Description |
|---|---------|-------|-------------|
| 1 | `ocr_confidence` | 0–1 | Average HTR model confidence |
| 2 | `overall_semantic_similarity` | 0–1 | Answer vs reference similarity |
| 3 | `mean_criterion_similarity` | 0–1 | Mean similarity across criteria |
| 4 | `min_criterion_similarity` | 0–1 | Weakest criterion similarity |
| 5 | `max_criterion_similarity` | 0–1 | Strongest criterion similarity |
| 6 | `std_criterion_similarity` | 0+ | Variability across criteria |
| 7 | `rubric_coverage` | 0–1 | Fraction of criteria with marks > 0 |
| 8 | `keyword_coverage` | 0+ | Total keyword matches |
| 9 | `answer_length_chars` | 0+ | Character count |
| 10 | `answer_length_tokens` | 0+ | Word count |
| 11 | `num_recognized_lines` | 0+ | HTR line count |
| 12 | `evaluation_confidence` | 0–1 | Evaluator's self-assessed confidence |
| 13 | `ai_preliminary_mark` | 0–max | AI-awarded mark |
| 14 | `max_marks` | 1+ | Maximum possible marks |
| 15 | `normalized_score` | 0–1 | AI mark / max marks |
| 16 | `mark_deviation_from_mean_criterion` | 0+ | Disagreement between score and evidence |

## Grading Error Labelling

A sample is labelled as a **grading error** when:

```
absolute_error = abs(AI_mark - expert_mark)
is_grading_error = absolute_error >= threshold
```

The **default threshold is 2.0 marks**.

This is **configurable** (not scientifically established):
```bash
# Via environment variable
export EVALISENSE_ERROR_THRESHOLD=1.5

# Via training script
python train_risk_model.py --error-threshold 1.5

# Via config.py
config.grading_error_threshold = 1.5
```

## Important: Data Integrity Rules

1. **Never present synthetic results as real performance** — always label synthetic data
2. **Never fabricate expert marks** — only real examiner marks count as ground truth
3. **If the dataset is too small, say so** — report "Insufficient evaluation data"
4. **Keep the feature extraction identical** between training and inference
5. **Track data sources** — every record's `metadata.source` should indicate its origin
